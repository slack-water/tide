Lesson 1

The Three-Layer Harness Model

One vocabulary for "is this skill safe" that isn't vibes — used in every lesson that follows.

You already know how to write a SKILL.md, wire a subagent, and register a hook. That's mechanics. What this course is actually about is a harder question: before you point one of those things at a live database or a broken CI pipeline, how do you know it's safe to trust with the blast radius involved?

"Follow good practices" isn't an answer — it's a hope. This lesson gives you a concrete model to reason with instead, borrowed from a framing that's specific to AI coding agents rather than general software architecture.

Primary source — read in full "Harness Engineering for AI Coding Agents" — Augment Code. This lesson compresses one framework from it; the article has more worked examples than fit here.

What a harness actually is

"Agent harness" gets used loosely — sometimes for the whole product (Claude Code), sometimes for an evaluation scaffold (the SWE-bench harness), sometimes conflated with a framework or SDK. The precise version: a harness is the layer wrapping a model that turns it into something able to act — it owns the tool interface, the control loop, and, most importantly for this course, the constraints on what the agent is allowed to do. A framework is a library for building harnesses. An SDK is an API. An orchestrator coordinates several agents. None of those are the thing itself.[1]

That last clause — constraints on what the agent is allowed to do — is the whole course. Everything below is about how to design those constraints deliberately instead of by accident.

The core claim: humans steer, agents execute

The Augment Code framework's thesis is blunt: reliability doesn't come from an agent being well-instructed and choosing to comply. It comes from deterministic constraints that don't depend on compliance at all. Telling an agent "follow our logging standard" is probabilistic. A linter that blocks the commit until it does is deterministic. The gap between those two is most of what separates a harness that occasionally embarrasses you from one you can actually trust with production systems.

That gap decomposes into three layers.

Layer 1 — Constraint Harnesses (feedforward)

Rules that shrink what's possible before the agent ever acts. A tool allowlist on a skill. A subagent's restricted permission set — remember, subagents don't inherit the parent's permissions automatically, so whatever you grant is the ceiling.[2] A read-only database credential. This layer doesn't correct bad behavior — it makes whole categories of bad behavior unreachable.

Layer 2 — Feedback Loops (corrective)

Signals returned mid-task that let the agent notice and fix its own mistake. A failing test. A lint error phrased as an instruction rather than a stack trace. Anthropic's tool-design guidance makes the same point from the other direction: error responses should "clearly communicate specific and actionable improvements, rather than opaque error codes or tracebacks."[3] A feedback loop only works if the agent can act on the signal — a cryptic error is not a feedback loop, it's noise.

Layer 3 — Quality Gates (enforcement)

Checks that block a bad outcome from landing regardless of whether the agent cooperated. CI refusing to merge. A PreToolUse hook that hard-blocks a DROP TABLE before it ever reaches the database, no matter what the agent intended. This is the layer that doesn't trust the agent at all — it trusts the gate.

The three layers aren't redundant — they fail differently. Constraint harnesses fail by being too narrow (the agent can't do its job). Feedback loops fail by being illegible (the agent can't act on the signal). Quality gates fail by being absent (nothing stops the bad outcome once the first two layers are bypassed or wrong). A harness worth trusting with real blast radius needs an honest answer at all three layers, not just the one that was easiest to build.

This is not a new idea — it's twelve-factor, renamed

The three-layer model is a specific case of discipline that predates agents entirely. The Twelve-Factor App encoded the same instinct for human-run services fifteen years ago:

  • Factor 5, build/release/run is a constraint harness — the agent should be structurally unable to run untested code against production, because the stages are separated, not because it was asked nicely.
  • Factor 11, logs as event streams is what makes feedback loops legible in the first place — you can't correct on a signal you can't read.
  • Factor 12, admin processes as one-off is the direct ancestor of "backup and restore run as their own scoped, disposable subagent invocation" — never folded into whatever else the main session happens to be doing.

You'll see this pattern repeat all course: agent harness engineering is mostly twelve-factor and SRE discipline, translated for a system that can also decide what to type next.

Where this is going

Each of your four target activities is currently weak at a different layer — that's next lesson's territory, but hold the shape of it now:

  • Database ops — usually missing quality gates. Nothing structurally stops a bad UPDATE.
  • Backup/restore — usually missing feedback loops. A silently corrupt backup looks identical to a good one until restore day.
  • CI debugging — usually missing constraint harnesses. The agent can see and touch far more of the repo than the failing job needs.
  • Feature development — usually has strong quality gates already (tests, CI) but weak constraint harnesses at the design stage — nothing stops overbuilding before a line of code is written.

Check your recall

1. A PreToolUse hook that hard-blocks any shell command containing DROP TABLE — which layer?

Reveal

3 — quality gate. It blocks the outcome regardless of agent intent or cooperation.

2. A skill's frontmatter restricts it to three read-only tools — which layer?

Reveal

1 — constraint harness. It removes the dangerous action from the possibility space before execution.

3. A failing test returns "expected 3 rows, got 0 — check the WHERE clause on line 42" instead of a raw stack trace — which layer?

Reveal

2 — feedback loop. It's a mid-task signal legible enough for the agent to self-correct.

4. From memory, name all three layers in order, feedforward to enforcement.

Reveal

Constraint harness, feedback loop, quality gate.
